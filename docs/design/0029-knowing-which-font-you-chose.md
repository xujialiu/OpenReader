# Knowing which font you chose

The reader could already choose how a book's text is set, from three answers: the system's font, a serif one, or a sans-serif one. Each of those describes a *kind* of font rather than a font. An owner picking the serif one was never told which face they actually got, and could not have picked a different serif one if they had wanted to.

So the list names faces now — Georgia, Times New Roman, Palatino, Avenir Next, Helvetica — with the book's own font at the top, still the default, because a book that ships its own typography keeps it until the owner says otherwise.

## Every name is shown in its own font

A list that names Georgia in the interface's own font asks the owner to already know what Georgia looks like. So each row is set in the font it offers, and choosing becomes a matter of looking rather than remembering.

The one exception is the book's own font at the top, which is set in the interface font because it is not any particular face — it is whatever that book shipped, and that differs from book to book.

## Nobody's book changes because of this

The two old answers still work. An owner who had chosen the serif kind now has Georgia, and one who had chosen sans-serif now has Helvetica. Those are the faces those two answers were already using, so a book that was open yesterday looks the same today.

## A name is a sample, not a promise

A book is not always all one script. A Chinese novel quotes an English title; an English book quotes a Chinese name. When it does, the choice the owner made applies to the part of the text it has letters for, and the rest is laid out in the system's nearest equivalent rather than in empty boxes.

That has a consequence worth stating plainly, because it can look like a fault: **two rows that look different in the list can set the same Chinese book identically.** Georgia and Palatino are both serif faces with no Chinese in them, so a Chinese paragraph under either falls to the same serif Chinese face. The preview differs because the preview is Latin. The book does not.

A Chinese book is still not stuck with one look, though. The serif names give it a serif Chinese face and the others give it a modern one, which is the same pair of answers the three kinds gave it before. What changed is only that the owner reading English now knows which face they picked.

## Chinese faces were offered, then taken away again

For a short while this list also offered four Chinese faces by name, so that an owner reading a Chinese novel could ask for a particular one rather than a kind.

Three of the four are not installed. Choosing them moved the tick, closed the list and changed nothing on the page, because the phone had no such font to give. Only one of the four was really there.

Nothing was broken by this — a font that is not installed quietly falls back to the nearest one the phone does have, so the text was always readable. But an option that takes your choice, shows it as chosen, and then does nothing is harder to make sense of than an option that was never offered. So they were taken out.

This is a fact about what was installed where it was tested, not a decision that Chinese faces do not belong here. A phone may well carry fonts a test machine does not, and if they turn out to be there, putting them back is a small change. Until somebody has looked at a real phone and seen them work, the list would rather offer five things that do something than nine things where four are silent.

## What was turned down

**Leaving the list at three kinds.** It is honest — it promises a kind and delivers a kind — and it is what the app did for a long time. It was turned down because "Serif" is not an answer to "which font am I reading this in".

**Keeping the one Chinese face that did work.** Tempting, and it would cost almost nothing. It was turned down for now because one Chinese face among five Latin ones raises the question of where the other three went, and that is a worse thing to leave on the screen than a clean list and a note in the record saying what to check.
