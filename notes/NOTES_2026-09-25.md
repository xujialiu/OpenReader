## The library's suspend stops the engine and keeps the session (2026-09-25 19:44)

Read out of `react-native-audio-api` 0.13.5 as installed, patch applied. `AudioContext::suspend` calls `IOSAudioPlayer::suspend`, which detaches the context's source node and calls `AudioEngine stopIfPossible` (stops the `AVAudioEngine` when no source or input is left); it does not touch `AVAudioSession`. `resume` calls `ensureActive:` on the session and `startPlaybackGraph`. Once the driver has started, a node's `start` no longer starts it: `AudioScheduledSourceNode::start` calls `AudioContext::start`, which returns `false` when `isInitialized_`. Both run through `PromiseVendor::createAsyncPromise`, which schedules them on a thread pool, so two calls made one after the other are not ordered. `onInterruptionEnd:` restarts the engine only from `AudioEngineStateInterrupted`, which `onInterruptionBegin` sets only from `Running`; `rebuildAudioEngineAndResumeIfNeeded` (route and configuration changes) calls `startEngine` only when the state is `Running`. A suspended engine is `Idle`, so neither restarts it.
