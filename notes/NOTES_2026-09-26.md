## Plugin service configuration differs from official API enrollment (2026-09-26 11:47)

The plugin's [Youdao translation adapter](https://github.com/windingwind/zotero-pdf-translate/blob/main/src/modules/services/youdao.ts) posts to aidemo.youdao.com/trans without a user key. Its Youdao dictionary adapter also needs no user key. These differ from [Youdao Zhiyun](https://github.com/windingwind/zotero-pdf-translate/blob/main/src/modules/services/youdaozhiyun.ts), which requires an application ID and secret. Saying that the plugin's Youdao dictionary needs API enrollment would be incorrect.

The [README service table](https://github.com/windingwind/zotero-pdf-translate#service) labels Google (both variants), CNKI, Haici, Youdao, iCIBA, Bing, DeepLX, Volcengine Web and Tencent Transmart as free without secrets. MyMemory has an anonymous allowance. LibreTranslate, MTranServer, NLLB, Pot and the configurable DeepLX route require external setup; absence of a key requirement does not establish zero hosting or upstream cost. No live availability tests were performed.

Inspection of the [dictionary adapters](https://github.com/windingwind/zotero-pdf-translate/tree/main/src/modules/services) found no key requirement for Youdao, Bing, Haici, Cambridge, Collins, FreeDictionaryAPI, Weblio or Gramota. Cambridge supports English source words, including English and Chinese definitions; Collins hardcodes English–Chinese; FreeDictionaryAPI hardcodes English. Weblio uses its English–Japanese site and Gramota its Russian lookup. These source observations do not establish permission to redistribute the fetched content.

Official free-tier checks differ from some README claims: [Azure Translator F0](https://azure.microsoft.com/en-us/pricing/details/translator/) lists 2 million characters per month; [MyMemory](https://mymemory.translated.net/doc/usagelimits.php) lists 5,000 characters daily anonymously and 50,000 with a valid email; [Gemini](https://ai.google.dev/gemini-api/docs/pricing) has model-dependent free tiers. [DeepL's current plan documentation](https://support.deepl.com/hc/en-us/articles/360021200939-DeepL-API-plans) says API Free is no longer available for new enrollment and its replacement Developer allowance is 1 million characters in total, not a monthly reset. The old API Free plan's 500,000 monthly characters must not be promised to new users. Compatibility of the new DeepL plan with the plugin was not tested.

## epub.js's scroll handling, read for Continuous: a synchronous scrollBy, and check() behind a 30 ms debounce with no maxWait (2026-09-26 12:06)

Read out of the bundled `@epubjs-react-native/core/lib/module/epubjs.js`, no device (#71, batch 4, built with no third simulator).

- `DefaultViewManager.scrollBy(t, e, i)` is `i && (this.ignore = !0)` then `this.container.scrollTop += e`, synchronous. The program's `nudge` is `rendition.manager.scrollBy(0, by, false)`, so a program scroll has moved `scrollTop` before any other task runs.
- `ContinuousViewManager.erase(t, e)` reads `container.scrollTop`, removes the view, and calls `this.scrollTo(0, i - r.height, !0)`: epub.js's correction is the same kind of assignment, made in the same task.
- `addScrollListeners` sets `this._scrolled = f()(this.scrolled.bind(this), 30)`, where `f = i.n(d)` and `d = i(46)`. The function behind it takes `leading`, `maxWait` and `trailing` options and has `cancel` and `flush`: lodash's `debounce`, called with no options, so trailing only and no `maxWait`. `scrolled()` enqueues `check()`, the appender, and emits `SCROLL`. So `check()` from scrolling runs only after 30 ms without a scroll event.

For Continuous: WebKit's `scrollTop` is whole CSS px (01:33), so a drift scrolls only when it has a whole pixel to pay. Below about 30 px/s its scroll events are at least 33 ms apart and `check()` runs between them. Above that, every frame scrolls and `check()` waits until the drift rests at a sentence's end. `renderAhead()` asks for the next section on each Clip cue either way.

`driftVelocity` at τ = 200 ms (glide.ts), simulated in Node at 60 Hz, semi-implicit Euler, exact pixels:

```
step 20: max 19.981 at 1s 19.18 at 0.5s 14.80
step 20 dt=2f: max 19.976
ramp 9px/s lag 3.45 expected 3.60
stair speed px/s min 7.1 max 10.4
```

The stair is 3 px every 330 ms, a word's worth along a 36 px line at the pace measured on Speechify.
