## XCTest can move two fingers together, through XCUIAutomation's own event synthesis (2026-09-24 02:15)

XCTest's public API has one-finger drags (`XCUICoordinate`) and two-finger pinches and rotations, and nothing that moves two fingers the same way. Xcode 27.0 (27A266a) ships the machinery privately: `strings` on `Platforms/iPhoneSimulator.platform/Developer/Library/Frameworks/XCUIAutomation.framework/XCUIAutomation` lists `XCPointerEventPath` with `initForTouchAtPoint:offset:`, `moveToPoint:atOffset:` and `liftUpAtOffset:`, `XCSynthesizedEventRecord` with `initWithName:interfaceOrientation:` and `addPointerEventPath:`, and `eventSynthesizer` / `synthesizeEvent:completion:`. `XCUIDevice.shared` answers `eventSynthesizer`. Called through their implementations from Swift (`test/manual-test/ios/TwoFingerProbe.swift`, `Fingers`), one path per finger, 36 pt apart, played together.

In Files on a new iPhone 17 simulator (iOS 27.0), in a folder of 60 one-line files shown as a list (rows 64 pt tall), two fingers from Row 02 to Row 06 over 1.2 s put Files into selection ("5 Items") with rows 2–6 selected.

The first attempt declared the completion block without `@escaping`. The drag still reached Files, which entered selection with nothing chosen, and the runner trapped at once with "closure argument passed as @noescape to Objective-C has escaped"; xcodebuild restarted the runner, ran 0 tests and then sat until killed.

## A gesture callback written inside a class meets `this` undefined (2026-09-24 03:00)

`.onStart((event) => this.begin(event.y))` and its siblings, as a class field, compiled and ran until the first update, which threw "Cannot read property 'move' of undefined" at `this.move` in a red box, and `end` did the same on finalize. In the bundle Metro serves, the worklets plugin moves each callback into a factory function, called with the variables it captured (`function useSweepTsx3Factory(_ref2) { … var useSweepTsx3 = event => sweep.begin(event.y); useSweepTsx3.__closure = { sweep }; … }`). An arrow function created there takes the factory's `this`, which is undefined, and `this` is not among what it captures. The same callbacks written against a captured variable (`sweep.begin(event.y)`) ran.
