## The Word well reports a grey as a grey, from the grid, from a stored grey and from the black swatch (2026-10-02 10:56)

The question (#118's docs lane): `@expo/ui` 57.0.19's `ColorPickerView.colorToHex` (`node_modules/@expo/ui/ios/ColorPickerView.swift`) reads `cgColor.components` as red, green, blue, and when there are only two, as a grey colour has (white, alpha), it takes the second, the alpha, as green. A grey would then come back tinted green. Measured on a new `iPhone 17 hl-ui` (D9B0651E-253B-4597-A23A-4ED231C1FAF1, iOS 27.0), the same Debug app and Metro 8141 as at 10:38, with a temporary `console.log` of the raw `onSelectionChange` string and `fromPicker`'s answer (removed before commit), through `HighlightWellProbe`:

- **A grey from the grid.** `testGreyFromGrid` tapped the grid's top row, sixth cell, with the word at Blue's 62 %: `#9999999E` → `{"color":"#999999","opacity":62}`. Moving the opacity slider to 42 % logged `#9999998B` … `#9999996C` → `#999999` at 55 … 42.
- **A grey stored by the app.** With both levels set to `#808080` (sentence 50 %, word 62 %) through the harness, `testSentenceOpacityToZero` logged `#8080806A` (42) down to `#80808000` (0), and `testWordOpacityDrag` 58 changes ending `#8080805B` → `{"color":"#808080","opacity":36}`.
- **The black swatch** under the grid: `#000000FF` → `{"color":"#000000","opacity":100}`; the swatch put the opacity back to 100 %. The slider to 47 % then logged `#000000D0` … `#00000078`.

No string had green standing for alpha: in each, green equalled red and blue. None of the three paths gave the well a two-component colour. The code path is there; what would reach it, if anything, was not found (the eyedropper and the Sliders tab were not tried).

During the sentence's `adjust` to 0, one string in the middle went back up: `#80808016` (9), then `#8080806B` (42), then `#80808011` (7), all within 2 ms, 687910–687912. 42 % is the value the app had saved 200 ms before, as `toPicker` writes it (`6B`). The last string was `#80808000`, and 0 was saved.
