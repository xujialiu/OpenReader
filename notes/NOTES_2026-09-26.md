## Zotero's Youdao dictionary adapter fetches webpages, not an open corpus (2026-09-26 11:40)

At upstream commit 0f16acd2b76ba286c79f008eff1ef8468ed8fc2f, [youdaodict.ts](https://github.com/windingwind/zotero-pdf-translate/blob/0f16acd2b76ba286c79f008eff1ef8468ed8fc2f/src/modules/services/youdaodict.ts) fetches https://www.youdao.com/w/ followed by the encoded lookup text, extracts HTML with a regular expression, strips tags, and constructs dict.youdao.com/dictvoice pronunciation URLs. It does not load a bundled dictionary. The repository's [license](https://github.com/windingwind/zotero-pdf-translate/blob/0f16acd2b76ba286c79f008eff1ef8468ed8fc2f/LICENSE) is AGPL-3.0; this does not establish a license to redistribute Youdao's dictionary content.

Youdao's separate [official dictionary API documentation](https://ai.youdao.com/DOCSIRMA/html/dictionary/api/ydcd/index.html) lists Chinese–English, English–Chinese and English–English dictionaries; requires contacting Youdao for activation; and prohibits caching, reuse and resale of returned data. Its endpoint is openapi.youdao.com/v2/dict with an application ID and signature, distinct from the plugin's webpage lookup. The [Youdao Cloud terms](https://ai.youdao.com/DOCSIRMA/html/agreement/terms/ydzyfwkt/index.html), sections 9.1–9.2, reserve content rights and restrict copying, scraping and caching without written permission. These sources provide no open-corpus license for offline import. No conclusion was drawn about whether the plugin author has separate permission, and the webpage adapter was not exercised live.

## Plugin service configuration differs from official API enrollment (2026-09-26 11:47)

The plugin's [Youdao translation adapter](https://github.com/windingwind/zotero-pdf-translate/blob/main/src/modules/services/youdao.ts) posts to aidemo.youdao.com/trans without a user key. Its Youdao dictionary adapter also needs no user key. These differ from [Youdao Zhiyun](https://github.com/windingwind/zotero-pdf-translate/blob/main/src/modules/services/youdaozhiyun.ts), which requires an application ID and secret. Saying that the plugin's Youdao dictionary needs API enrollment would be incorrect.

The [README service table](https://github.com/windingwind/zotero-pdf-translate#service) labels Google (both variants), CNKI, Haici, Youdao, iCIBA, Bing, DeepLX, Volcengine Web and Tencent Transmart as free without secrets. MyMemory has an anonymous allowance. LibreTranslate, MTranServer, NLLB, Pot and the configurable DeepLX route require external setup; absence of a key requirement does not establish zero hosting or upstream cost. No live availability tests were performed.

Inspection of the [dictionary adapters](https://github.com/windingwind/zotero-pdf-translate/tree/main/src/modules/services) found no key requirement for Youdao, Bing, Haici, Cambridge, Collins, FreeDictionaryAPI, Weblio or Gramota. Cambridge supports English source words, including English and Chinese definitions; Collins hardcodes English–Chinese; FreeDictionaryAPI hardcodes English. Weblio uses its English–Japanese site and Gramota its Russian lookup. These source observations do not establish permission to redistribute the fetched content.

Official free-tier checks differ from some README claims: [Azure Translator F0](https://azure.microsoft.com/en-us/pricing/details/translator/) lists 2 million characters per month; [MyMemory](https://mymemory.translated.net/doc/usagelimits.php) lists 5,000 characters daily anonymously and 50,000 with a valid email; [Gemini](https://ai.google.dev/gemini-api/docs/pricing) has model-dependent free tiers. [DeepL's current plan documentation](https://support.deepl.com/hc/en-us/articles/360021200939-DeepL-API-plans) says API Free is no longer available for new enrollment and its replacement Developer allowance is 1 million characters in total, not a monthly reset. The old API Free plan's 500,000 monthly characters must not be promised to new users. Compatibility of the new DeepL plan with the plugin was not tested.

## Both plugin Google adapters use a no-key web endpoint (2026-09-26 12:22)

Delegated source and documentation inspection, without translation requests. At commit 0f16acd2b76ba286c79f008eff1ef8468ed8fc2f, [google.ts](https://github.com/windingwind/zotero-pdf-translate/blob/0f16acd2b76ba286c79f008eff1ef8468ed8fc2f/src/modules/services/google.ts) implements Google and Google(API) with the same /translate_a/single?client=gtx route on translate.google.com and translate.googleapis.com respectively. Neither requires a Google Cloud credential; the optional secret field replaces the base URL. The [README](https://github.com/windingwind/zotero-pdf-translate/blob/0f16acd2b76ba286c79f008eff1ef8468ed8fc2f/README.md#service) labels both free and without a secret. The API label does not make this the official Cloud Translation endpoint.

[Google Cloud pricing](https://cloud.google.com/products/translate/pricing) lists the first 500,000 characters of NMT text translation per month covered by a $10 monthly credit. [Setup](https://docs.cloud.google.com/translate/docs/setup) requires a project, API activation and billing; [authentication](https://docs.cloud.google.com/translate/docs/authentication) is also required. These are separate from the plugin's no-key routes.

The [consumer website](https://translate.google.com/) supports language detection. The [official Cloud v2 API](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate) detects source language when source is omitted and requires target. Neither establishes a documented guarantee for sl=auto on the plugin's web route, which remains untested. Detecting the source does not itself choose the reverse target for Chinese–English translation.

The plugin's [default preferences](https://github.com/windingwind/zotero-pdf-translate/blob/0f16acd2b76ba286c79f008eff1ef8468ed8fc2f/src/modules/defaultPrefs.ts) explain its choice of CNKI for zh-CN users by Google Translate's availability in mainland China. This is upstream's recorded rationale, not a measurement of the owner's network. Adding Google or changing the accepted default service remains a product question, not an outcome of this audit.
