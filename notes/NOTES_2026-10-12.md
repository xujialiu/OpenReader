## epub.js splices an id into an XPath too (2026-10-12 22:06)

A two-section book with section 1 out of reach (60 filler paragraphs before
it), and `rendition.display` of section 1's heading
`epubcfi(/6/4!/4/2[Newton's_laws])`, each way from a fresh page:

| How the place reached `display` | Result |
| --- | --- |
| the library's `'…'` | `SyntaxError: Unexpected identifier 's_laws'`; nothing displayed |
| as a string, as a JSON literal would give it | `SyntaxError: The string did not match the expected pattern.` from `document.evaluate`; the promise never settled; section 1's frame `hidden/hidden` |
| as a string, id assertion removed | resolved; visible; heading 548 px from the top |
| as a string, `stepsToXpath` quoting the id | resolved; visible; heading at 548 px |
| control, `[p1]` with and without the id | resolved; visible; 596 px both ways |

The cause is `EpubCFI.stepsToXpath`'s `@id='` + id + `'`. epub.js resolves by
XPath whenever no `ignoreClass` element is present, which with the rendition's
default `ignoreClass: ""` is always. With only the library's splice quoted,
the vitest repro's (b) went green over a stub `rendition.display` that never
runs this.
